# Полная установка Hermes BNN на macOS Apple Silicon

## 1. Что устанавливается

Это полный обезличенный программный комплект, включая Intake. Он создаёт отдельного владельца, профиль, ключи местных служб, пустую память, задачи, корпус и библиотеку Zotero. История, документы, идентичность, аккаунты, OAuth и ключи автора не входят. Закрытая и открытая копии имеют одинаковое содержимое; различается доступ к репозиторию.

Все программы и их среды находятся в частях архива одного выпуска. Это полная поставка, а не набор ссылок на прежние закрытые репозитории. Исходники ядра, подписанные поставки GSD/Research/Foundation, Python, Java, Node, базы и библиотеки включены. Операционная система и право доступа к внешним платным сервисам не распространяются.

Проверенная платформа: **нативная macOS 26.5.1, Apple Silicon arm64**. На другой версии macOS установщик останавливается до создания состояния: изоляция вычислений привязана к проверенному системному исполнителю. Docker и WSL не требуются. Проверка на физически другом Mac не проводилась. Не отключайте проверку версии ОС и хешей для обхода несовместимости.

Программные версии: Memory `2.0.0-dev.44`, Intake `0.14.3`, GSD Engine `3.0.3`, адаптер GSD `0.2.13-hermes-0.22.2-r6`, Research `0.44.0b2`, Foundation `0.14.0b1`. Основа Hermes: commit `d923a5eb487a17c0a68801bba9ef0f56c81040a8` с включёнными местными исправлениями. Детальный состав: [COMPONENTS.md](https://github.com/olegeklepikov-collab/hermes-bnn-full/blob/main/docs/COMPONENTS.md), точные версии и суммы: `configuration/full-source.json`, `bundle-manifest.json` и манифесты самих компонентов.

## 2. Скачать полный выпуск

Откройте Releases своего репозитория и выберите один выпуск. Скачайте **все** части `Hermes-BNN-Full-*.tar.gz.partNNN`, `SHA256SUMS`, `RELEASE.json` и `download.sh`. Достаточно одного репозитория. Не смешивайте части разных выпусков. Git clone сам по себе не скачивает многогигабайтные среды из Releases.

Для открытого репозитория можно запустить включённый `download.sh`: он получает части и проверяет их SHA-256. Для закрытого нужны собственный вход GitHub через `gh` либо ручная загрузка через браузер. Чужие пароли и токены не входят.

```sh
bash download.sh "$HOME/Downloads/Hermes-BNN-distribution"
cd "$HOME/Downloads/Hermes-BNN-distribution"
shasum -a 256 -c SHA256SUMS
```

`SHA256SUMS` включает как части, так и итоговый архив. Помощник сначала проверяет части, затем собирает архив, затем проверяет его. При ручной загрузке объедините части по возрастанию номера, используя точное имя из `RELEASE.json`:

```sh
cat Hermes-BNN-Full-*.tar.gz.part[0-9][0-9][0-9] > Hermes-BNN-Full.tar.gz
```

Имя собранного файла должно совпадать с полем `archive.name` в `RELEASE.json`; используйте именно его для сверки. Штатные macOS `gzip`, `tar`, `curl` и `shasum` достаточны; zstd и отдельная Python для распаковки не нужны. Внутренний манифест проверяет целостность файлов; сам по себе он не является независимой подписью автора. Подписи поставщиков Research/Foundation проверяются отдельно.

## 3. Подготовить место и установить R

Выберите **новую пустую папку**, не каталог существующего Hermes. Нужно не менее 40 ГБ свободного места для скачивания, распаковки и начального состояния; для корпусов и резервов добавьте место. Не используйте сетевой каталог с неподдерживаемыми правами или файловую систему, теряющую символические ссылки и режимы доступа.

```sh
mkdir -p "$HOME/Applications/HermesBNN-New"
tar -xpf Hermes-BNN-Full.tar.gz -C "$HOME/Applications/HermesBNN-New"
cd "$HOME/Applications/HermesBNN-New/Hermes-BNN-Full"
```

Если имя итогового архива отличается, подставьте `archive.name`. Не распаковывайте поверх действующего экземпляра.

Для R нужен официальный **R 4.6.1 arm64**. Пакет включён: `Installers/R-4.6.1-arm64.pkg`. Он устанавливает `/Applications/R.app` и `/Library/Frameworks/R.framework`. Если уже установлен совместимый R, повторная установка не нужна. Если установлен другой R, не заменяйте его без собственного решения; сначала оцените совместимость своих проектов. Общий установщик BNN сам системные каталоги не переписывает.

```sh
pkgutil --check-signature './Installers/R-4.6.1-arm64.pkg'
open './Installers/R-4.6.1-arm64.pkg'
```

Завершите системную форму. Пароль администратора вводится только в macOS. Подписи и двоичный хеш R проверяются до создания профиля. `NativeEnvironment` содержит также аварийные копии программ; это не команда заменить глобальные приложения или Homebrew.

## 4. Инициализировать отдельный экземпляр

```sh
./install.sh
```

Установщик последовательно проверяет полный состав, платформу и системный R; переносит только программные пути; проверяет подписи и исходники Research/Foundation и каноническую поставку GSD; создаёт собственные UUID и местные ключи; инициализирует пустые SQLite, Beads, Dolt и служебные пространства; подключает одну общую память и Intake к существующему Host.

Ожидаемые свидетельства: `Hermes/state/bootstrap.json`, `fresh-verification.json`, `full-intake-install.json`, `full-platform-verification.json`. Первичные таблицы пусты, проверки целостности успешны, пять обязательных контроллеров зарегистрированы. Неавторизованные вызовы отклоняются по существу, а не из-за отсутствующего контроллера.

Повторная установка поверх созданного профиля запрещена. При ошибке сохраните журнал и состояние; сначала проверьте выполненные эффекты. Не удаляйте ключи, базы или квитанции ради повторного запуска. Для нового испытания используйте новую распаковку в другой папке. Вариант восстановления собственных данных описан в [BACKUP_RECOVERY.md](https://github.com/olegeklepikov-collab/hermes-bnn-full/blob/main/docs/BACKUP_RECOVERY.md).

Все последующие команды выполняются из корня `Hermes-BNN-Full`:

```sh
source './Hermes/environment.sh'
PY='./Hermes/hermes-agent/venv/bin/python'
./Hermes/bin/hermes --version
./Hermes/bin/bd-bnn version
./Hermes/Dolt/bin/dolt version
```

## 5. Запустить местные службы

```sh
"$PY" neutral_services.py start
"$PY" neutral_services.py check
```

Проверяются собственные AgentMemory/III, Graphiti/Neo4j, Zvec и пустая локальная Zotero. Адреса: 127.0.0.1, порты 65000–65006 и 65030; точная таблица: [OPERATIONS.md](https://github.com/olegeklepikov-collab/hermes-bnn-full/blob/main/docs/OPERATIONS.md). Занятые порты вызывают отказ, чужие процессы не завершаются. Без ключа Voyage эмбеддинговая служба не запускается. Работоспособность порта не доказывает модельное извлечение знаний.

Остановка:

```sh
"$PY" neutral_services.py stop
```

## 6. Подключить собственную модель и эмбеддинги

```sh
./Hermes/bin/hermes auth add openai-codex --type oauth --no-browser
./Hermes/bin/hermes auth status openai-codex
```

Используйте адрес и код, выданные именно вашим экземпляром. Базовая модель настроена как `gpt-6.1-sol`, усилие `xhigh`; доступность проверяется вашим аккаунтом. Подписка ChatGPT и ключ API эмбеддингов являются разными доступами. Авторизации автора не переносятся.

Voyage: создайте свой ключ на https://dashboard.voyageai.com/ . Остановите собственный агент и местные службы, затем:

```sh
"$PY" neutral_configure.py voyage
"$PY" owner_rebind.py --stopped
```

Ключ вводится скрыто в Терминале. Используется `voyage-4-large`, 1024 измерения, отдельные назначения `query` и `document`. Подтверждение записи ключа не является проверкой вызова. После запуска служб проверьте настоящий запрос, индексирование собственного синтетического факта, поиск перефразированием и кэш. Graphiti и Cognee должны использовать собственный модельный маршрут; их присутствие в среде не объявляется успешным извлечением без модельного ответа.

Точный предварительный счётчик токенов для проверенного OAuth-маршрута отсутствует; фактический расход учитывается после ответа. Неподтверждённые исходы не обнуляются, обязательный контекст не отсекается. Работа делится на адресные части.

## 7. Подключить поисковые и научные сервисы

Следуйте [SERVICES.md](https://github.com/olegeklepikov-collab/hermes-bnn-full/blob/main/docs/SERVICES.md). Включены общие инструменты BNN и назначенные исследовательские пути UDR; это не только восемь старых методов поиска. Точные схемы, фильтры и адреса находятся в [SERVICE_CATALOGUE.json](https://github.com/olegeklepikov-collab/hermes-bnn-full/blob/main/docs/SERVICE_CATALOGUE.json) и `configuration/services.template.json`.

После настройки ключа/входа повторно привяжите **собственную конфигурацию**, сохраняя неизменную пару Memory/Intake:

```sh
"$PY" owner_rebind.py --stopped
```

Для этой фиксированной поставки не запускайте прежние команды `services build/revise/contracts/activate`: они предназначены для разработки нового выпуска и могут создать несовместимую с Intake версию Memory. Изменение схем или программ требует отдельной квалификации; изменение своего секрета не требует пересборки программ.

## 8. Telegram и рабочая библиотека

Создайте собственного бота через https://t.me/BotFather . Откройте `./Hermes/bin/hermes setup` и настройте Telegram, токен и **собственный числовой ID разрешённого пользователя** через защищённый ввод. Не используйте ботов или ID автора. Обязательно ограничьте вход, прежде чем запускать шлюз.

Для команд `/gsd`, `/udr` и `/intake` одного списка Telegram в `.env` недостаточно: общий Host отдельно проверяет `command_owners`. Добавьте туда **свой числовой Telegram ID строкой**, при остановленных процессах. Следующая команда спрашивает ID локально и изменяет только собственный экземпляр:

```sh
"$PY" - <<'PYOWNER'
import json, os, re
from pathlib import Path
path = Path('Hermes/Memory/settings.json')
owner = input('Ваш числовой Telegram ID: ').strip()
if not re.fullmatch(r'[0-9]+', owner):
    raise SystemExit('Нужен числовой ID пользователя, не имя и не токен бота')
config = json.loads(path.read_text())
owners = config.setdefault('command_owners', [])
if owner not in owners:
    owners.append(owner)
temporary = path.with_name(path.name + '.owner-new')
with temporary.open('x') as stream:
    json.dump(config, stream, ensure_ascii=False, indent=2)
    stream.write('\n')
temporary.chmod(0o600)
os.replace(temporary, path)
print('Собственный владелец команд записан; требуется следующая привязка')
PYOWNER
"$PY" owner_rebind.py --stopped
```

Не копируйте чужой ID. При ошибке `module_command_owner_required` сверяйте именно этот список, фактического отправителя и профиль. Никакие обязательные контроли для этого не отключаются.

После изменения собственной конфигурации и при остановленных процессах выполните `owner_rebind.py --stopped`. Доступные команды шлюза смотрите через `./Hermes/bin/hermes gateway --help`; запускайте только свой профиль. Не включайте автозапуск второго процесса с тем же ботом.

Zotero начинает с отдельной пустой библиотеки на порту 65030, синхронизация выключена. Для синхронизации войдите в собственный аккаунт и оцените объём хранения; не подменяйте библиотеку автора. Инструменты записи требуют разрешения собственного Zotero. Проверяйте запись, чтение, вложение и обратимую уборку собственной пробной записи.

## 9. Начать работу и проверить полный цикл

```sh
./Hermes/bin/hermes
```

В отдельной беседе запросите `/intake status`, `/gsd status`, `/udr status`. Intake по умолчанию `off`; доступны `/intake auto`, `/intake on`, `/intake off`. Выключение Intake не отключает общие обязательные контроли. GSD и UDR/Foundation имеют собственные переключатели. Не восстанавливайте истёкшее поколение GSD сбросом срока; создайте новое штатно.

Собственный конечный пример: файл с before=20 и after=30; постановка и декомпозиция; чтение с происхождением; расчёт +10 и +50%; версии свидетельств; сохранение заметки и отчёта; повторное чтение; закрытие задачи; возобновление из сохранённого состояния; доставка Markdown через разрешённый механизм. Причинность из двух чисел не следует. Проверяйте фактический полученный файл, а не обещание отправки.

Уровень: установка → подключение → успешный локальный вызов → настоящий модельный/сетевой цикл → доставка. Отсутствующая авторизация не заменяется имитацией. Система завершает все доступные необходимые проверки сама; рекомендации аналитику не являются обязательным внешним барьером выпуска.

## Первое включение Zotero и графической среды

Устанавливайте рабочий экземпляр в обычную локальную папку, например `$HOME/Applications/HermesBNN-New`, вне управляемого облачного каталога. В испытательном облачном каталоге подпись Zotero корректна, но macOS задержала его регистрацию в LaunchServices на системном вызове выдачи sandbox extension; локальный API не поднялся. Это не успешная проверка Zotero, и причина за пределами логики Intake.

Серверную часть можно включить независимо:

```sh
"$PY" neutral_services.py start --no-gui
"$PY" neutral_services.py check --no-gui
```

Такой отчёт явно содержит `zotero.status=not_checked`, а не фиктивный успех. Для полной проверки на своей обычной локальной установке остановите службы и выполните обычные `start` и `check` без этого параметра. Если macOS требует подтверждение запуска приложения, выполните его самостоятельно в штатном системном интерфейсе. Не отключайте Gatekeeper и не заменяйте подпись приложения. При повторном отказе сохраните журнал и проверьте путь, доступы macOS и отсутствие занятого порта; работоспособность API Zotero должна быть подтверждена отдельно.

# Общие исследовательские сервисы BNN и UDR

## Порядок подключения

Программные адаптеры и зафиксированные схемы включены в комплект. Авторизации нового владельца исходно отсутствуют. Каталог является снимком известного интерфейса: фактическую доступность продукта, метода и плана подтверждает ответ поставщика. Состояния прежнего аккаунта не считаются состояниями нового владельца.

1. Установить платформу. Остановить собственные процессы и местные службы.
2. Создать собственный доступ на странице поставщика. Секрет не отправлять в чат, Markdown, аргументы команды или репозиторий.
3. Для ключей использовать скрытый локальный ввод:

```sh
./Hermes/bin/hermes-services setup-key exa
```

Вместо `exa` доступны `firecrawl`, `tavily`, `keenable`, `nimble`, `parallel`, `consensus`, `openalex`, `semanticscholar`, `pubmed`, `tinyfish`, `elicit`, `synapse`. Parallel привязывает Search и Task; Keenable основной и SELECT; TinyFish основной MCP и API. При недоступном API плане запись ключа не создаёт доступ.

4. Для OAuth использовать собственную подготовленную форму:

```sh
./Hermes/bin/hermes-services oauth scite
```

Допустимые имена: `scite`, `undermind`, `alphaxiv`, `pendar`, `openalex`, `tinyfish`, `wiley`, `elicit`. Читайте фактически запрашиваемые права. Если поставщик не принимает подключение, сохраняйте отказ; не объявляйте успех. Discovery может сохранить новый каталог, но не вводит неизвестные методы в фиксированный выпуск без проверки.

5. Техническую почту для Crossref и NCBI вводить самостоятельно:

```sh
./Hermes/bin/hermes-services contact
```

6. После изменения ключей/входов при остановленных писателях:

```sh
source './Hermes/environment.sh'
PY='./Hermes/hermes-agent/venv/bin/python'
"$PY" owner_rebind.py --stopped
```

7. Запустить службы и свой Hermes. Через штатное обнаружение инструментов получить точную схему, выполнить один малый запрос, дочитать результат, сверить фактического поставщика и хеши. Затем проверить такой же доступ назначенного сборщика UDR. Общее имя `context`/Service dispatcher и передаваемые им инструменты не требуют фиктивного запуска UDR для обычной работы BNN.

Не запрашивать более десяти точных имён в одном `tool_describe`. Полный перечень имён и параметров: [SERVICE_CATALOGUE.json](https://github.com/olegeklepikov-collab/hermes-bnn-full/blob/main/docs/SERVICE_CATALOGUE.json). Исполнитель может разрешать только часть объявленного поставщиком каталога; фильтр сохранён в `configuration/services.template.json`. Публикация, удаление, внешняя запись и платный запуск не получают разрешение от одного факта подключения.

## Проверять содержательно

Для каждого реально подключаемого сервиса: статус → точная схема → малый поиск → чтение исходника → сохранение происхождения → чтение результата родителем и назначенным ребёнком → восстановление/продолжение по устойчивому ID. Исходный текст, обзор ИИ, аннотация, отрывок и метаданные различаются. Для асинхронного исследования дождаться конечного состояния; очередь не равна завершению. Для длинных ответов дочитать все страницы.

Повтор идентичного ID и входа читает сохранённый результат; неизвестный исход не запускается повторно вслепую. HTTP 429/403, недостаточный план и отсутствие оригинала сохраняются как ограничения. Подключение одного сервиса не требует и не доказывает работоспособность остальных.

## Пуск и остановка

Из корня комплекта:

```sh
source './Hermes/environment.sh'
PY='./Hermes/hermes-agent/venv/bin/python'
"$PY" neutral_services.py start
"$PY" neutral_services.py check
./Hermes/bin/hermes
```

AgentMemory HTTP 65000; Neo4j Bolt 65001 и HTTP 65004; III 65002/65003; шлюз эмбеддингов 65005 при наличии Voyage; представление AgentMemory 65006; Zotero 65030. Только 127.0.0.1. Собственные квитанции процессов: `Hermes/state/services`. Порты не являются внешней авторизацией.

Перед сменой конфигурации завершите/приостановите свою работу, остановите собственный CLI/шлюз, затем `"$PY" neutral_services.py stop`. Не применяйте широкую остановку всех Hermes или принудительное удаление блокировок. Не запускайте второго получателя Telegram с тем же токеном.

## Полный рабочий цикл

1. Создать или продолжить настоящую рабочую карточку и задачу Beads. Сохранить цель, область, ограничения и критерии достаточности.
2. Включить уместный Intake. Выбрать уровень eMVP, MVP, Standard, eStandard, High Stakes либо Critical Infrastructure; уровень не подменяет качество свидетельств.
3. Раскрыть корпус и недостающую информацию. Отказ пользователя от ответа сохраняется, но не отменяет доступного независимого поиска. Ограничения опроса наследуются детьми.
4. Выбрать методы открытого каталога: концептуализация → дименсионализация → операционализация → инструментализация; парадигма → теория → модель → методология → метод → методика → инструмент; предметные и причинные трассы. Новые методы допустимы с обоснованием.
5. UDR хранит устойчивые источники и планы. Сборщики получают точную роль, источники, разрешённые инструменты и квитанции. Не наследуют произвольную запись, публикацию или отправку.
6. Прочитать оригиналы адресными частями, сохранить покрытие и происхождение. Результат поиска, извлечённый текст, доставка текста модели и смысловая проверка имеют разные статусы.
7. GSD применять к макроциклу или конкретной подзадаче, сохраняя ограниченный состав ролей. Не вызывать тот же завершённый цикл рекурсивно. Новая информация создаёт новую версию, а не переписывает прежний продукт.
8. Сохранить расчёты, основания, неопределённость и версии данных. Найденные графом/векторами записи повторно связать с оригиналами SQLite/документами.
9. Выполнить все доступные необходимые проверки и системную приёмку. Внешнее человеческое ревью является рекомендацией по конкретным аспектам, а не обязательным запретом выпуска.
10. Сохранить конечный Markdown, повторно прочитать, проверить целостность и фактическую передачу. Длинный результат отдавать файлом с кратким содержательным сообщением.

## Документы любого размера

Среда разбора PDF, офисных документов, XLS/XLSX, CSV, SQL/JSON и текстов включена. Штатный путь: регистрация исходного файла → неизменный оригинал и хеш → разрешённый parser → адресные единицы → `research_source` → квитанции чтения/доставки → покрытие корпуса.

`raw_acquired_requires_host_intake` означает полученный оригинал, требующий разбора. Poppler, PyMuPDF, pdfplumber или xlrd сами по себе не являются завершённой исследовательской цепочкой. Исходный PDF не объявляется прочитанным после импорта. Для таблиц учитываются листы, строки, формулы и ограничения извлечения; для PDF страницы, рисунки, сканы/OCR и таблицы. Выполнение макросов и исходного SQL не является чтением данных и не разрешается автоматически.

Большой корпус обрабатывается разбиением по устойчивым единицам. Для каждого фрагмента сохраняются хеш исходника, границы, хеш фрагмента и признак продолжения. Дочитывать до `complete`/конца, а не до первого предварительного просмотра. Не заявлять «тысячи страниц прочитаны», если подтверждены только извлечение или индексирование. Неподдержанный формат и невосстановимый фрагмент фиксируются как остаток. Конечное время, память и место ограничены; произвольный объём не означает один неограниченный запрос.

## Долгое продолжение и контекст

Состояния хранятся вне истории чата. Продолжение спустя время начинается с рабочей карточки, версий, квитанций, сохранённых ограничений, неизвестных эффектов и действительного поколения GSD. `/gsd resume` не продлевает срок и не обнуляет расход; при истечении требуется новое поколение. Нельзя превращать неизвестный сетевой исход в неисполненный ради повтора.

Оперативный контекст содержит цель и текущий шаг; рабочий содержит адресные источники и зависимости; долговременный хранит семантические, эпизодические и процедурные записи. Глубокая идентичность находится отдельно от исследовательского корпуса. Поставляется пустое основание новой идентичности; личность автора отсутствует.

Переполнение разрешается сжатием истории штатным способом и разбиением работы. Обязательное ядро и зависимости не отсекаются. При отказе обязательного контроллера зависимый путь останавливается; отключение контроля не является лечением. Проверять причину, доступность профиля, сроки и состояние исполнителей.

| Закончился контекст | Сначала проверить эффекты прошлого шага, затем штатное сжатие или адресное продолжение; обязательное не усекать |

| Нет ключа/плана | Прямо указать недоступный путь; не приписывать ответ другого сервиса исходному |

Наблюдаемость: местные журналы ядра, служб, контроллеров, Store и квитанции артефактов. Они могут содержать собственные данные; не публиковать целиком. Уведомления пользователю должны сообщать полученный содержательный результат, остаток и следующий шаг, а не только техническую операцию.

## Первое включение Zotero и графической среды

Устанавливайте рабочий экземпляр в обычную локальную папку, например `$HOME/Applications/HermesBNN-New`, вне управляемого облачного каталога. В испытательном облачном каталоге подпись Zotero корректна, но macOS задержала его регистрацию в LaunchServices на системном вызове выдачи sandbox extension; локальный API не поднялся. Это не успешная проверка Zotero, и причина за пределами логики Intake.

Серверную часть можно включить независимо:

```sh
"$PY" neutral_services.py start --no-gui
"$PY" neutral_services.py check --no-gui
```

Такой отчёт явно содержит `zotero.status=not_checked`, а не фиктивный успех. Для полной проверки на своей обычной локальной установке остановите службы и выполните обычные `start` и `check` без этого параметра. Если macOS требует подтверждение запуска приложения, выполните его самостоятельно в штатном системном интерфейсе. Не отключайте Gatekeeper и не заменяйте подпись приложения. При повторном отказе сохраните журнал и проверьте путь, доступы macOS и отсутствие занятого порта; работоспособность API Zotero должна быть подтверждена отдельно.

# Резерв, восстановление и обновление

## Чистая поставка и собственный резерв

Этот выпуск является полной программной поставкой **для нового владельца**. Он не является восстановлением частного состояния автора. Закрытая копия не содержит дополнительных секретов. Для отката своего установленного экземпляра нужно отдельно сохранить его состояние, собственные ключи, личность и данные.

Остановить собственные CLI/шлюз и службы, убедиться в отсутствии записывающих задач. Сохранить целиком `Hermes`, корневые средства установки/работы, `configuration`, `NativeEnvironment`, `Installers`, `Intake` и документы. Если R установлен глобально, сохранить его точную версию и официальный установщик; автоматическое восстановление `/Library` и `/Applications` не выполнять.

Полный собственный резерв содержит секреты и требует шифрования, закрытого доступа и отдельного безопасного хранения средства расшифрования. Архивировать при остановленной записи. Не считать обычное копирование открытой Neo4j/Dolt/SQLite согласованным резервом. Использовать либо штатный снимок каждой службы, либо остановку всех собственных писателей и холодную копию.

## Восстановить собственное состояние

1. Сверить источник, SHA-256 и полноту всех частей.
2. Восстановить в новую пустую папку. Сохранить исходный повреждённый экземпляр до выяснения причины.
3. Сверить ОС, архитектуру, R и системный изолятор. Не переименовывать чужую несовместимую среду в поддержанную.
4. Не запускать `install.sh` поверх сохранённого владельца: он предназначен для чистой инициализации.
5. При том же абсолютном пути и той же машине проверить целостность и собственные базы, затем запускать только один комплект служб/бота.
6. При новом пути требуется перенос собственных программных привязок, сертификатов и конфигураций в остановленном состоянии с проверкой сохранённых данных. Чистая поставка автоматизирует новый экземпляр; произвольный перенос уже заполненного владельца этим установщиком не объявлен проверенным. Нельзя менять только одну абсолютную строку либо создавать ссылку на профиль другого владельца.
7. Повторно проверить историю задач, оригиналы, граф, векторное пространство, отчёт и квитанции; затем продолжать незавершённые работы. Неизвестные расходы/эффекты не стирать.

## Обновлять безопасно

Обновлять смежную копию, сохраняя согласованную пару Memory `2.0.0-dev.44` и Intake `0.14.3`. Сверять манифесты и интерфейсы ядра, parser, compute, общих пяти контроллеров и SDK. Не применять upstream upgrade поверх местных исправлений без сравнения. Подписанные исходники поставщиков не переписывать.

Для своего секрета или допустимой конфигурации при остановленных процессах используется `owner_rebind.py --stopped`. Он сохраняет существующую программу, проверяет её хеши, собственные файлы авторизации и заново оформляет привязку Intake. Изменение программы или каталога инструментов требует отдельной квалификации и нового выпуска. Старые `services build/revise/contracts/activate` в этой фиксированной поставке не являются командой повседневной настройки.

Переносимость dev.44 реализована адресным адаптером исходного пути: `path_relocations` связывает неизменное происхождение parser/compute с текущим корнем и новым owner_id. Произвольный корень, другой владелец, выход через symlink, иной Python/ОС/изолятор отклоняются. Исходные `/Volumes/...` в запечатанных дескрипторах являются происхождением компонента, а не активным доступом к старой машине.

## Отменить Intake без потери работы

Способы `set_enabled(False)` и возврата `True`, остановка писателей и точные аргументы находятся в `Intake/INTEGRATION.md`. Отключается необязательная подготовка, сохраняются общая политика приёмки, нативный Host, пять контроллеров и данные. Удаление баз, отключение обязательного контроля или установка двух копий одного плагина не являются откатом.

## Минимальная приёмка после восстановления

Целостность SQLite; настоящие версии Beads/Dolt; единственный общий плагин; пять зарегистрированных контроллеров; отдельная проверка parser/compute; чтение известного оригинала; поиск со ссылками на оригинал; сохранение и повторное чтение; продолжение своей незавершённой задачи; собственный входящий Telegram и доставка Markdown. Наличие программы и успешный порт не заменяют эти результаты.

# Обезличивание и происхождение

Поставляется программная часть для нового владельца. Не включены действующие data/auth.json, .env с ключами, приватные ключи подписи, токены Telegram, Voyage и поисковых сервисов, SOUL/глубокая идентичность автора, базы памяти, документы, проекты, библиотека Zotero, пользовательские векторы, журналы бесед и история Git автора.

Исходники компонентов, их лицензии, авторство, публичные ключи проверки, тестовые синтетические примеры и описания форматов ключей сохраняются. Публичный тестовый RSA-образец в документации OpenSSL не является секретом владельца. Прежние контрольные суммы в явно названном provenance относятся к происхождению, а не к текущему выпуску.

В 20 неподписанных квитанциях сборки Homebrew личный домашний путь заменён на `__BUILD_USER_HOME__`; код и двоичные файлы не изменялись. Посторонние FinderInfo/ResourceFork в копии Zotero исключаются, чтобы сохранить проверяемость исходной подписи; подпись приложения не заменяется самодельной. Архив формируется без расширенных атрибутов macOS.

Запечатанные дескрипторы native parser/compute могут содержать исходный путь программного корня как происхождение. После инициализации проверяемый адаптер связывает этот корень с текущим каталогом и UUID нового владельца. Это не доступ к прежним файлам. Проверки чужого владельца, неверного исполнителя, отсутствующей привязки и чтения исходной авторизации должны отклоняться.

Memory dev.44 является явно отмеченной местной производной dev.43: адаптер подтверждённого переноса пути применяется также к compute; содержание GSD и подписанных SDK не изменено. Intake 0.14.3 сохраняет алгоритмы 0.14.2 и закрепляет новую совместимую основу. Этот новый парный выпуск не переписывает отдельные репозитории Intake 0.14.2 и не меняет действующий BNN.

Публичная и закрытая копии побайтно совпадают по программному комплекту. Закрытый репозиторий не предназначен для загрузки действующих секретов. Для собственного приватного состояния нужен отдельный зашифрованный резерв.
