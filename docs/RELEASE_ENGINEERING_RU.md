# Разработка и выпуск Hermes BNN

## Области

`product/` содержит точные программные исходники платформы. `locks/` закрепляет полный нейтральный программный снимок зависимостей и происхождение исходников. Программы не копируются из работающего агента при каждой сборке. Исходная основа 01.11.2026 импортирована из ранее проверенной обезличенной поставки. Это зафиксированный начальный снимок зависимостей, не доказательство независимой пересборки каждого стороннего компонента.

## Условия хоста

Первый поддержанный профиль: нативная macOS arm64, квалифицированная ОС 26.5.1 и включённая исходная R 4.6.1. Подписанные источники поставщиков сохраняются. Нет Docker, WSL или автоматического повышения прав. Другой Mac не испытан. Тестовая и разрабатываемая установки имеют собственные HOME, HERMES_HOME, состояние, идентичность, Beads, Dolt и порты; исходные учётные данные не наследуются.

## Один рабочий цикл

1. Рабочая ветка задачи и критерии в Beads.
2. Исправление в product/ и воспроизведение в tests/.
3. Быстрые проверки: `python3 -B -m unittest discover -s tests/release_engineering -v`.
4. Зафиксировать согласованные исходники, испытания и закрепления.
5. Сборка: `python3 -B packaging/release_cli.py build --version ВЕРСИЯ`. Она отвергает незафиксированные изменения, проверяет полный снимок зависимостей и создаёт цельный архив.
6. Проверка подписи и архива: `python3 -B packaging/release_cli.py verify КАТАЛОГ`.
7. Установка именно из архива: `python3 -B packaging/release_cli.py qualify КАТАЛОГ --environment test`.
8. Проверить оставшиеся критерии RELEASE_ACCEPTANCE.json и сохранить сведения с точным хешем. Пропуск не считается успехом.
9. Допускается тот же программный комплект. Продвижение не пересобирает его. Рабочую установку меняют только отдельной предусмотренной процедурой с разрешением владельца, резервом и проверкой миграций.

## Подпись

Манифест RELEASE.json подписывается SSH Ed25519, пространство имён bnn-release-v1. Закрытый ключ хранится вне Git в .operator/keys с правами 0600. Проверка использует доверенный trust/allowed_signers из исходного репозитория, а не произвольный ключ из проверяемого архива. При новой установке доверенный открытый ключ закрепляют отдельно. Подпись доказывает происхождение байтов, не смысловую корректность агента. Резерв закрытого ключа выполняется оператором в закрытом резерве, не в открытом выпуске.

## Полнота и обновления

Каждый новый номер имеет полный установочный архив. Разбиение на части допускается как транспорт одного выпуска. Исторические исправления пользователь вручную не накладывает. Текущая команда qualify не обновляет существующую пользовательскую базу: для неё требуются отдельные проверенные миграции и процедура обновления. Нельзя выдавать чистую установку за проверку обновления или восстановления.

## Публикация и CI

Главный источник: закрытый hermes-bnn-full-private. Публичный hermes-bnn-full и самостоятельные пакеты Intake являются производными экспортами. В GitHub Actions выполняются только автономные проверки; здесь нет рабочих ключей или постоянного исполнителя на Mac владельца. Нативная квалификация выполняется локально. Автоматическое развёртывание в prod отсутствует.

## Состояние и откат

Программы и данные имеют разные жизненные циклы. Не откатывать пользовательские данные при обычной смене программы. Совместимость схем и обратимость миграции проверяются на отдельной копии. Предыдущие архивы не удаляются. Отложенные работы сохраняют задания, историю и учёт ресурсов; истёкшее поколение GSD не продлевается обновлением программы.
