## Что исправлено

1. Новый владелец может передавать файлы до настройки необязательных эмбеддингов Voyage. Существующие секреты по-прежнему проверяются, отсутствие обязательного ключа контроллера по-прежнему блокирует путь.
2. Операторское подключение Telegram обновляет подтверждение точной конфигурации Intake в остановленном профиле. Подписанные зависимости, история и учёт ресурсов не изменяются. Произвольное изменение настроек таким подтверждением не разрешается.
3. При длинном пути профиля шлюз использует существующий локальный TCP-свидетель работы цикла вместо недопустимого AF_UNIX адреса. Штатный потребитель статуса уже поддерживает этот протокол; проверки жизнеспособности не отключены.
4. Сборщик принимает каталоги, введённые собственными исходниками в более новом нейтральном наборе зависимостей. Точные права каталогов и каждый посторонний файл проверяются; чужие файлы не становятся разрешёнными из-за родительского каталога.
5. Проверка пакета Intake выбирает wheel из закреплённого манифеста, а не из старого номера в имени файла.

## Воспроизведение

1. Установить цельный кандидат в отдельный TEST по `product/docs/INSTALL_MACOS.md`. Проверить подпись и SHA-256 до установки.
2. Настроить собственные ChatGPT и отдельного Telegram-бота по [TEST_TELEGRAM_RU.md](TEST_TELEGRAM_RU.md). Подготовка токена не является доказательством сетевой работоспособности.
3. Выполнить `python3 -B packaging/check_live_roundtrip.py КАТАЛОГ_КАНДИДАТА` в исходном репозитории с квалифицированной выбранной TEST-установкой.
4. Создать синтетический Markdown в зарегистрированном рабочем проекте, независимо вычислить SHA-256 и размер.
5. Через настоящий клиент Telegram отправить запрос на `memory_working(bind)`, `memory_artifact(register)`, `memory_artifact(send)` и `memory_artifact(status)`. Передать точный ожидаемый SHA-256; при неизвестном результате не повторять отправку.
6. Проверить сохранённый результат, однократность отправки, `server_bytes_verified`, размер, сумму, адресата и отсутствие неучтённых модельных попыток. Проверить фактическое вложение в клиенте получателя.

Проверки восстановления и обновления пользовательской базы этим сценарием не подменяются. Передача собственных доступов TEST в его новую установку не объявляется переносом всей базы данных.
