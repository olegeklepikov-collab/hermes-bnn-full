# Отдельный Telegram для TEST

Это настройка учётного доступа в уже установленной тестовой среде, без изменения программы выпуска и без переноса ключей рабочего экземпляра.

1. Создайте отдельного бота через https://t.me/BotFather, командой `/newbot`. Не используйте бота, который уже обслуживается рабочим экземпляром.
2. В каталоге исходников запустите `python3 -B packaging/telegram_test_setup.py --bot ИМЯ_БОТА --owner ЧИСЛОВОЙ_ID_ВЛАДЕЛЬЦА`. Для известных занятых ботов передайте повторяемый параметр `--forbid ИМЯ`. Значение токена в команду не включается.
3. Откройте напечатанный адрес `http://127.0.0.1:ПОРТ/` на этой же машине. Введите полный токен в защищённое поле и нажмите «Проверить и сохранить в TEST». Если машина недоступна удалённо, требуется отдельный защищённый перенос секрета; локальная форма из интернета недоступна.
4. Форма проверяет имя через `getMe`, отказывает при действующем webhook, сохраняет явный список разрешённых пользователей. В остановленном профиле штатная процедура Intake обновляет подтверждение точной конфигурации после изменения только раздела доставки; остальные настройки и история сохраняются. Токен получает права `0600`, не попадает в Git, архив, адрес страницы, параметры процесса или квитанцию.
5. Откройте бота в Telegram и нажмите Start. Само сохранение токена не доказывает приём сообщения или передачу файла.

Выбор среды берётся только из `.operator/environments.json`, раздел `test`, и сверяется с квалификацией и идентификатором экземпляра. Каталог вне разрешённого TEST отклоняется. Рабочие службы не перезапускаются. Шлюз автоматически не запускается: сначала оператор проверяет область профиля и отсутствие второго опрашивающего процесса.

Состояние подготовки находится в `telegram-connection` рядом с каталогом конкретной тестовой установки. `form.json` содержит локальный адрес без секрета. `connection.json` подтверждает сохранение, но не сетевую приёмку. До изменений сохраняются точные `before-memory-settings.json`, `before-config.yaml`, `before-intake-deployment.json`, при наличии `before-env`, а также `before-state.json`. Эти файлы могут содержать настройки доступа и должны оставаться вне Git.

При ошибке после начала записи повтор автоматически запрещён. Сначала сверяют сохранённые эффекты. Для отмены останавливают только шлюз этого TEST, восстанавливают предыдущие конфигурации и их `intake-deployment.json`, прежнюю `.env` (либо удаляют созданную `.env`, если `env_existed=false`), затем удаляют только два созданных этой операцией файла `private/telegram.token` и `private/telegram-recipient.json`. Исходные пользовательские данные и чужие службы не затрагиваются. Отключение на машине не отзывает токен в Telegram; отзыв выполняется отдельно через BotFather при необходимости.

Первое реальное подключение выявило пропуск обновления подтверждения Intake. Он исправлен в операторском помощнике. Восстановление первоначальной попытки допускается через `telegram_test_setup.py --apply-home КОРЕНЬ_HERMES --apply-case КАТАЛОГ_TELEGRAM_CONNECTION --repair-intake` с собственными Python, `HERMES_HOME` и `PYTHONPATH` остановленного TEST. Этот путь требует существующей квитанции подключения, проверяет исходную подпись и хеш прежних настроек, допускает только точное изменение доставки и сохраняет историю и учёт ресурсов. Произвольные изменения настроек таким способом подтвердить нельзя. Не отключайте проверку конфигурации для устранения ошибки загрузки.

Сетевые критерии: реальное входящее сообщение владельца, корректный ответ, фактический вызов модели с завершённым учётом ресурсов, отправка Markdown через штатный механизм BNN, повторное скачивание и совпадение контрольной суммы. Отправку через операторский Bot API отдельно от Hermes нельзя считать испытанием всего пути. Получение человеком и проверка серверных байтов являются разными свидетельствами.

## Если владелец находится у другой машины

1. Оператор использует Python из выбранной тестовой установки и запускает `packaging/remote_telegram_token.py prepare`. Нужна включённая в среду библиотека `cryptography`. Требуется уже подготовленная локальная форма с подтверждёнными ботом, экземпляром и владельцем.
2. Команда создаёт отдельный ключ RSA только для этой передачи. Закрытый ключ с правами `0600` остаётся в `.operator/telegram-transfer/`, вне Git и выдаваемого файла. Владелец получает только `Hermes-BNN-TEST-Telegram.html` из `remote-input` конкретной тестовой установки.
3. Владелец скачивает HTML, открывает его в браузере на своём устройстве, вводит токен и нажимает «Зашифровать». Затем копирует зашифрованный блок в рабочий чат или скачивает `.jwe`. В ранее выданной форме кнопка может сразу предлагать скачивание. Форма не обращается к сети и очищает поле после шифрования. Шифрование: стандарт JWE, RSA-OAEP-256 и AES-256-GCM. В HTML нет закрытого ключа или токена.
4. Оператор принимает только зашифрованное вложение: `packaging/remote_telegram_token.py accept --file ПУТЬ_К_JWE`. Проверяются целостность, адресат, экземпляр, бот, владелец и срок 24 часа. Токен расшифровывается в памяти и передаётся в существующую локальную форму; сохраняется тем же штатным путём, что и при местном вводе. Значение не печатается и не входит в параметры процессов.
5. После успешного сохранения передача отмечается использованной. Повторная запись остановлена. Настоящий приём сообщения и передача файла проверяются отдельно. Если импорт оборвался, сначала проверяют эффекты, затем решают вопрос о повторе.

Проверка криптографического пути: `TEST_PYTHON -B -m unittest discover -s tests/operator_crypto -v`. Она выполняет реальный код HTML через Web Crypto в Node.js с вымышленными ключами, расшифровку Python и отрицательные случаи изменения тега, другого экземпляра и истёкшего срока. Это не равнозначно ручному испытанию интерфейса во всех браузерах.

### Ввод со смартфона

Команда `packaging/remote_telegram_token.py prepare-mobile` создаёт вариант для размещения на отдельной статической HTTPS-странице. Он содержит открытый ключ, имя бота, случайные идентификаторы и хеш закрытой привязки. Местные пути и числовой ID владельца в этот вариант не включаются. Закрытая привязка, ключ и импорт остаются в `.operator`. Публикуется только `mobile-public/index.html`, а не весь каталог подготовки.

После размещения оператор проверяет HTTPS и побайтовое совпадение страницы с локальным файлом. Владелец открывает ссылку в Safari или Chrome, вводит токен, нажимает «Зашифровать», затем «Скопировать зашифрованный блок» и отправляет только этот блок в чат. При запрете доступа к буферу обмена поле с шифротекстом выделяется для ручного копирования. Исходный токен не копируется этой кнопкой. Импорт принимает точную исходную или мобильную привязку одного запроса; произвольные адресаты не допускаются.

Статическая страница не имеет сервера приёма секретов: `connect-src 'none'`, `form-action 'none'`, нет внешних сценариев и аналитики. После использования оператор закрывает временную страницу; использованный запрос в любом случае больше не принимается. Испытание страницы на настольном браузере нельзя выдавать за аппаратную проверку всех смартфонов.
