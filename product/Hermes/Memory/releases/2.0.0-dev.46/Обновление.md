# Memory 2.0.0-dev.46

Добавлено чтение сохранённого типизированного продукта дочернего исполнителя через work_team/udr_team action=result. Требуются task_id и expected_revision из status; offset/page_size задают полные последовательные фрагменты. Каждый ответ содержит product_sha256 и fragment_sha256. native_output_sha256 относится к исходному тексту модели; представление чтения явно обозначено canonical_json_of_saved_typed_product. Последняя страница не приравнивается к чтению всего продукта.

Область чтения проверяется действующей привязкой работы, сеанса и профиля. Не возвращаются секретные полномочия или сырой handle. Продукт needs доступен для удовлетворения потребностей. Результаты завершённого/приостановленного UDR можно прочитать без возобновления исполнения; требования текущей области и включённого модуля сохраняются. Данные и научные утверждения не повышаются автоматически из unreviewed. Схема SQLite, источники GSD/Research/Foundation и обязательные контроли не менялись.

Дефект воспроизведён настоящим дочерним агентом в Memory dev.45. Автоматические проверки нового чтения находятся в tests/release_engineering/test_native_task_results.py исходного репозитория. Нативное подтверждение нового полного кандидата фиксируется отдельно после сборки. Этот компонент не устанавливают вручную поверх действующего агента: он входит в следующий цельный выпуск.
