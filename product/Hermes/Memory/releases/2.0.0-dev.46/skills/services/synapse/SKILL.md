# synapse

Состояние при сборке: documented_REST_adapter. Если доступ ожидается или список методов пуст, сообщи фактическое условие владельцу; не придумывай схемы и не запускай другой интерфейс для обхода ограничения.

1. Вызови service_catalog(service="synapse") и выбери метод по смыслу. Схему выбранного метода получи с method.
2. Передай точные аргументы через service_read, service_job или service_write согласно effect. Отказ и отсутствие доступа не заменяй другим сервисом без явного указания.
3. Прочитай полный ответ страницами до next_offset=null; продолжай через service_result. Полный сохранённый ответ не равен полному чтению статьи. Отмечай исходный текст, аннотацию, выдержку и машинный обзор отдельно.
4. Идентификатор длительного задания сохрани в рабочей памяти/Beads; продолжай его штатным методом статуса, не создавай повтор. Неизвестный исход сначала проверяет оператор.
5. Для UDR/work_team передай точные service_calls; для G/S/D используй assigned_service_calls по ролям. Рекурсивное делегирование и расширение полномочий запрещены.
6. Внешние постоянные изменения требуют отдельного допуска владельца к точному вводу. Исследовательские задания запускаются в рамках порученной работы с сохранением ID и обязательным контролем хоста. blocked не обходи другим интерфейсом. Не покупай подписки и не управляй ключами.
