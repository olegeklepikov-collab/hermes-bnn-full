# Экспертная работа Hermes BNN

## Выбор пути
Используйте этот навык для предметной экспертной задачи или её узла. Сначала выясните цель, ограничения и критерий окончания. `work_plan` ведёт единственный первичный граф Beads; свяжите текущую беседу с выбранной задачей через `memory_working`. Обычные чтение, вычисление и передача результата не требуют отдельного GSD-цикла.

## Предпосылки
Обязателен плагин `bn-common-memory` и собственный сервер MCP `context`. Отсутствие исполнителя или отказ допуска не являются успешным выполнением. `tool_describe` принимает не более десяти имён за вызов.

## G/S/D
Загружайте адресный контракт через `gsd_catalog`, `gsd_contract`, `gsd_context`. `gsd_work` исполняет выбранную процедуру полного каталога; `gsd_analyze` поддерживает G, S, D, GS, GD, SD, GSD. Выбирайте состав по имеющимся входам: G порождает версии, S проверяет основания, D различает версии. Не подменяйте недостающий обязательный вход предположением. `gsd_research` запускает полный цикл.

Шесть профилей: eMVP, MVP, Standard, eStandard, High Stakes, Critical Infrastructure. Уровень определяется последствиями ошибки и каноническим контрактом. Повышение ставки важнее удобства. Требуемый контекст с замыканием зависимостей должен поступить полностью; при переполнении делите работу. Передавайте источники по ролям через `assigned_resources`; проверочные свидетельства не передавайте G как материал порождения. Модельный продукт остаётся unreviewed до предметной приёмки.

Один родитель выбирает следующий предметный узел. Листовые G/S/D не запускают GSD, исследование или других детей. Повторный самостоятельный узел допустим после завершения прежнего: это не рекурсивная оркестрация.

## UDR и Foundation
`udr_workspace` создаёт или продолжает долговременное исследование. `udr_source` сохраняет источник и фактически прочитанный объём, `udr_note` — вывод со ссылками, `udr_finish` — отчёт с повторным чтением и импортом Foundation. Исследование сохраняет идентичность и источники после паузы; срок аренды исполнителя не является сроком жизни исследования. При частичном завершении сначала читайте состояние и сохранённый отчёт; не переписывайте их ради повтора.

## Команда
`work_team` работает по обычной задаче Beads, `udr_team` — по существующему исследованию. Сначала `action=plan`, затем `run`; независимые листья запускаются параллельно. Назначайте точные версии `resources`: files, code, records, documents, library, data. Роли: collector, analyst, reviewer, parser, computation. Укажите обязательные инструменты в `required_tools`. Если источник или право отсутствует, ребёнок возвращает типизированную потребность. Родитель удовлетворяет её через `continue` с текущей ожидаемой редакцией; прежний результат сохраняется. `delegate_task` не является разрешённым обходным путём.

## Документы и контекст
Инвентаризируйте корпус. Извлечение не равно чтению: используйте адресные `document_read`, `document_status`, `document_partition` и проверяйте полноту требуемой фазы. Для файлов используйте `memory_files`; для кода — `memory_code`; для библиотеки — `memory_library`; для версий данных — `memory_data`. Дополняйте только необходимым материалом; не отсекайте обязательные источники. Перед сжатием обязательная контрольная точка сохраняет историю и ограничения. После сжатия полномочия не берутся из модельного пересказа.

## Режимы и результат
Пользовательские команды `/gsd auto|off|status` и `/udr on|off|status` действуют только на текущую беседу. UDR и Foundation отключаются вместе, общая память и защита остаются. Не представляйте модельный вызов как пользовательскую команду. Сообщайте предметный результат завершённого шага, оставшийся вопрос и следующий шаг; технические события без изменения результата не требуют отдельных уведомлений. Неизвестный исход нельзя считать нулевым расходом или разрешением повторить действие.

## Проверка
Отличайте сохранение, фактическое исполнение и предметную достоверность. Сверяйте первичный файл, версии, происхождение, свидетельства чтения и терминальные квитанции детей. Выдавайте готовый большой результат файлом после проверки разрешённой доставки. Указывайте границы чтения, неопределённость и непринятые части.

## Полный документ и выдача

Если нужен полный документ либо ответ не помещается в сообщение, сохрани полный Markdown через `memory_artifact(action=create,file_name,content,request_id)`; готовый собственный файл используй через `register` с хешем. Затем `send` и `status`. Создание происходит в отдельном каталоге результата текущего проекта, без перезаписи. Для новой редакции нужен новый request_id. Крупный документ разбивай на полные нумерованные части; обязательный материал не отсекай. Эти действия доступны без GSD и UDR.

Не объявляй документ переданным по сохранению файла. Получение API не означает открытия пользователем. Неизвестную отправку не повторяй без наблюдения эффекта. Статус описывает цель, содержательный сделанный шаг, текущий вопрос, следующий результат и препятствие; не перечисляй вызовы, хеши и служебные идентификаторы без запроса. Не публикуй одинаковые сведения повторно.

## Адресный поиск и продолжение

Для известного MEM-/SRC-ID используй адресное чтение: `memory_recall(query=ID)` не выполняет широкий поиск или новый эмбеддинг. Для явной стратегии передай `need` с purpose, expected_output, sufficiency, scope=current_authorized_scopes. `targeted` ищет по заданной цели, `semantic` — по смыслу, `lexical` — только местно.

`snapshot` читает явную карту versions(id,revision,content_hash), страницы по next_offset. Это выбранная карта версий, а не автоматически полный слепок всей работы. Отозванные/закрытые версии остаются недоступными; пропуски не замещай текущими. Карты больше 256 элементов дели на полные пакеты, не отсекай.

`example` требует объект, цель, среду, существенные признаки и неизвестное. Найденное сходство не доказывает переносимость: отдельно сравни отличия по оригиналам. `heuristic` требует trace_id и step_reason; одинаковый запрос/страница без новой первичной базы или прав останавливается. После остановки читай полученные основания, меняй обоснованный вопрос либо сообщай предел; новое имя trace_id не является новым свидетельством. Пустой ввод не запускает сбор. Ни один результат ранжирования не означает полного обхода корпуса.

После run/status прочитайте продукт каждого листа через `work_team` или `udr_team` action=result: task_id, expected_revision из status, offset=0 и page_size до 8192. Пока has_more=true, используйте next_offset, сохраняя редакцию и проверяя один product_sha256. Склейте текст всех фрагментов. Один последний фрагмент не означает чтения всего продукта. Статус succeeded доказывает завершение исполнителя; findings и источники берите из прочитанного продукта. Статус unreviewed не превращается автоматически в проверенный научный вывод.
