## Полный каталог объявленных методов

- `search`: read. Consensus: relevance-ranked semantic search over 400M+ peer-reviewed papers (Semantic Scholar, OpenAlex, PubMed). Use it to look up papers for a scientific query asked in plain language. Returns ranked records: title, authors, year, journal, citations, abstract and link (DOI on paid plans). Filters: study design, sample size, journal quartile, medical mode, years.  All filters are optional: only apply them when the user explicitly asks.  Example query → filter mappings: - "what does the evidence say about metformin for longevity?"     → query="metformin longevity mortality",       medical_mode=True, exclude_preprints=True - "recent peer-reviewed RCTs on SGLT2 inhibitors for heart failure"     → query="SGLT2 inhibitors heart failure outcomes",       year_min=2022, exclude_preprints=True, study_types=["rct"] - "long-term studies of statin side effects (1+ year)"     → query="statin adverse effects long-term",       duration_min=365, medical_mode=True - "what is dark matter?"     → query="dark matter"  (no filters — general question) - "coffee and cognition, excluding top-tier Q1 journals"     → query="coffee cognition", sjr_min=2  For a research question that needs synthesis, analysis or more than one lookup, use `create_thread` instead: it runs Consensus's scientific research agent and returns a cited answer (async, takes a few minutes).
- `create_thread`: write. Create a new research thread and dispatch the Consensus research agent.  Runs Consensus's specialized scientific research agent: it plans and runs many searches, reads full text, follows citations forward and backward, analyzes and reflects on the evidence, and returns a cited synthesis. Use it for any research question that needs synthesis or analysis rather than a single lookup: what the evidence says, comparisons, mechanisms, literature reviews, or multi-step research tasks. For a single lookup of papers matching a scientific query, use `search`. Also use this to list the user's library collections or the papers in one, create or rename one, or save papers into one.  This dispatches an autonomous research agent that reasons and executes many steps on its own. Delegate the entire request in a single call: pass a full brief covering every part of what the user asked, including ordered sub-tasks ('identify A, then find B related to A'). Do not decompose the request into successive create_thread/add_to_thread calls, and do not do intermediate research yourself to hand it a narrower question — that yields worse results and costs several minutes per hop.  After calling, wait at least 30 seconds (use a sleep/timeout) before each get_thread poll. Pro results typically finish within ~3 minutes; Deep results may take up to ~10 minutes. Polling faster returns cached 'running' results and does not speed up the agent.
- `add_to_thread`: write. Add a new interaction to an existing research thread.  Only for a genuinely new follow-up the user raised after the previous interaction's results were delivered. Never chain this onto your own create_thread call to work through parts of a single request — put the whole request in the create_thread brief instead.  Call this only once get_thread reports the thread 'idle' or 'failed'. While an earlier interaction is still running this returns an error: keep polling get_thread until status is no longer 'running', then call add_to_thread again.  The new interaction runs asynchronously. After calling, wait at least 30 seconds (use a sleep/timeout) before each get_thread poll. Polling faster returns cached 'running' results and does not speed up the agent.
- `get_thread`: read. Poll a research thread and return the grounded answer when ready.  The returned status is 'running' while the agent works and 'idle' when a final answer is available. Wait at least 30 seconds (use a sleep/timeout) between get_thread calls. Pro results typically finish within ~3 minutes; Deep results may take up to ~10 minutes. Calling more frequently than every 30 seconds returns cached 'running' results and does not speed up the agent.  When status is 'idle', write the interaction's `document` field to a file or the client's artifact/canvas/side-panel surface — do not paste it inline in chat and do not paraphrase it. Every inline citation marker, [N.M] (quote M of paper N) or a bare [N], must be preserved exactly; they are already hyperlinked to the cited papers.
- `find_threads`: read. List the signed-in user's research threads.  Requires a signed-in Consensus account. Returns thread metadata including a deep-link URL.
