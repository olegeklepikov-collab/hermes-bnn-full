# Общие исследовательские сервисы BNN и UDR

## Порядок подключения

Программные адаптеры и зафиксированные схемы включены в комплект. Авторизации нового владельца исходно отсутствуют. Каталог является снимком известного интерфейса: фактическую доступность продукта, метода и плана подтверждает ответ поставщика. Состояния прежнего аккаунта не считаются состояниями нового владельца.

1. Установить платформу. Остановить собственные процессы и местные службы.
2. Создать собственный доступ на странице поставщика. Секрет не отправлять в чат, Markdown, аргументы команды или репозиторий.
3. Для ключей использовать скрытый локальный ввод:

```sh
./Hermes/bin/hermes-services setup-key exa
```

Вместо `exa` доступны `firecrawl`, `tavily`, `keenable`, `nimble`, `parallel`, `consensus`, `openalex`, `semanticscholar`, `pubmed`, `tinyfish`, `elicit`, `synapse`. Parallel привязывает Search и Task; Keenable основной и SELECT; TinyFish основной MCP и API. При недоступном API плане запись ключа не создаёт доступ.

4. Для OAuth использовать собственную подготовленную форму:

```sh
./Hermes/bin/hermes-services oauth scite
```

Допустимые имена: `scite`, `undermind`, `alphaxiv`, `pendar`, `openalex`, `tinyfish`, `wiley`, `elicit`. Читайте фактически запрашиваемые права. Если поставщик не принимает подключение, сохраняйте отказ; не объявляйте успех. Discovery может сохранить новый каталог, но не вводит неизвестные методы в фиксированный выпуск без проверки.

5. Техническую почту для Crossref и NCBI вводить самостоятельно:

```sh
./Hermes/bin/hermes-services contact
```

6. После изменения ключей/входов при остановленных писателях:

```sh
source './Hermes/environment.sh'
PY='./Hermes/hermes-agent/venv/bin/python'
"$PY" owner_rebind.py --stopped
```

7. Запустить службы и свой Hermes. Через штатное обнаружение инструментов получить точную схему, выполнить один малый запрос, дочитать результат, сверить фактического поставщика и хеши. Затем проверить такой же доступ назначенного сборщика UDR. Общее имя `context`/Service dispatcher и передаваемые им инструменты не требуют фиктивного запуска UDR для обычной работы BNN.

Не запрашивать более десяти точных имён в одном `tool_describe`. Полный перечень имён и параметров: [SERVICE_CATALOGUE.json](SERVICE_CATALOGUE.json). Исполнитель может разрешать только часть объявленного поставщиком каталога; фильтр сохранён в `configuration/services.template.json`. Публикация, удаление, внешняя запись и платный запуск не получают разрешение от одного факта подключения.

## Проверять содержательно

Для каждого реально подключаемого сервиса: статус → точная схема → малый поиск → чтение исходника → сохранение происхождения → чтение результата родителем и назначенным ребёнком → восстановление/продолжение по устойчивому ID. Исходный текст, обзор ИИ, аннотация, отрывок и метаданные различаются. Для асинхронного исследования дождаться конечного состояния; очередь не равна завершению. Для длинных ответов дочитать все страницы.

Повтор идентичного ID и входа читает сохранённый результат; неизвестный исход не запускается повторно вслепую. HTTP 429/403, недостаточный план и отсутствие оригинала сохраняются как ограничения. Подключение одного сервиса не требует и не доказывает работоспособность остальных.
